# CVA6/Ariane ports on Kria (K26) and Zynq UltraScale+ boards — clock frequency survey

Compiled 2026-10-28. Method: authenticated `gh` API (repo, code and issue search; raw file reads), web search, and PDF text extraction. Nothing was downloaded or executed apart from reading pages and raw files.
User baseline, for comparison only: unmodified `cv64a6_imafdc_sv39` on a KR260 (`xck26-sfvc784-2LV-c`), Vivado 2026.1, `pl_clk0`. It meets timing at 90.9 MHz and fails at 100 MHz (WNS −0.553 ns).
This file adds only facts that are new relative to `../Frecuencia del CVA6 en FPGA/*.md`. Items already known there (Cuomo 2307.04148, SoC-all-core, turing-house KR260, issues #77/#226/#1749/#2700, ESP VCU118) are not repeated.

**Legend.** *Target* = clock the build is configured for. *Routed WNS* = slack from the project's own routed timing report. *Implied fmax* = 1000/(T − WNS), my arithmetic. It is only a lower bound, because Vivado stops optimizing once the constraint is met. *Claim* = stated in text, with no report.

## Q3: open items, now resolved

- **ESP on ZCU102/ZCU106: yes, an Ariane tile is the configured CPU, but the support is preliminary.** Both defconfigs set `CPU_ARCH = ariane` with one `cpu` tile, and `BASE_FREQ_MHZ ?= 75`. In `top.vhd`, `sys_clk(0) <= chip_refclk` and `refclk => chip_refclk`, and the wrapper maps `pl_clk0 => chip_refclk`. CPU and memory tiles therefore run at **75 MHz**. Memory is PS DDR through an AHB-to-AXI bridge to an HP port (PR #84). There is no per-CPU `constraints/.../ariane/` directory, unlike VC707/VCU118. The board is still "(WIP)" in `socs/README.md`. Maintainer, 2023 (#191): "the user was able to successfully run baremetal applications, but was not able to boot Linux on the SoC". No timing report has been published.
- **richie-hesoc: the 100/50/50 MHz PL clocks do NOT apply to a CVA6 host. This is a strong inference.** The repository tree contains no `cva6`/`ariane` files, and code search finds 0 hits. Its Zynq flows (`fpga/utils/hero/{zcu102,zcu104,ultra96_v2}/hero_exil*.tcl`, `PL0_REF_CTRL__FREQMHZ` 100/50/50) are HERO "exil" designs, where the PS **Cortex-A53 is the host** and the PULP cluster sits in the PL. HERO README: "The 64-bit ARMv8 Cortex-A53 of the processing system (PS) serves as host CPU". The CVA6 host is a VCU128 target "under development". Richie docs give no FPGA board, clock or FPU info for a CVA6 host ("FPGA Deployment … TBD"). FPU status: unknown.

## Inferences (not stated by sources)

- On the **same K26 -2LV part**, Accemic's FPU-less RV64IMAC plus trace logic closed at 71.1 MHz with +0.6 ns. Derumigny/Hummel chose 60 MHz for RV64GC+H with HPDCache. **No public K26 design runs CVA6 above ~71 MHz.** The user's 90.9 MHz, met with the FPU, is the highest K26 figure known. Caveat: neither source pushed for fmax.
- On ZCU104 (-2, 0.85 V), a 100 MHz default for an FPU+H+HPDCache CVA6 was abandoned for 75 MHz together with an RTL timing fix. This suggests 100 MHz did not close for the dual-core/shared-HPDCache variant. Unverified: there is no report.
- Numbers above 100 MHz on Zynq US+ exist only for **32-bit, no-FPU** CV32A6 on a **-3** part (189 MHz, Thales). The FORTH 100 MHz Ariane has unknown config and board. Neither is comparable to RV64GC on a -2LV K26.

## Gaps

- FORTH HPC Asia 2024 full text (board, part, Ariane config, FPU, timing) was blocked (ACM 403). The U. Crete thesis PDF failed TLS verification.
- Thales 189 MHz: exact device, Vivado version, and whether it is a routed fmax or a constraint are not stated.
- Derumigny ZCU104/KR260: no timing reports or WNS published, and no KR260 Linux-boot evidence.
- ESP ZCU102/106 and cheshire-env-nvdla ZCU106: no timing reports and no Linux evidence.
- Not found: any Ultra96, Genesys ZU, Alinx AXU, TUL PYNQ-ZU or Avnet ZUBoard CVA6 port. Searches of CSDN/Zhihu/Bilibili, Qiita/Zenn, Hackster, Reddit and AMD forums returned nothing relevant. One unread lead: IPSJ ComSys2022-009 (Japanese paper surfaced by the search, HTTP 503).
- GitHub code search covers only indexed default branches. Forks with board support on non-default branches (as Derumigny's once was) can be missed.
